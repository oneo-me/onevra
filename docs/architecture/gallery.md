# Gallery design

The gallery is a standalone example and a native review surface for public components, icons and direct MyGo APIs. It must run without any consumer application.

## Separation from the library

The [entry point](../../source/examples/gallery/main.go) owns startup, appearance selection and shutdown. The [internal gallery](../../source/examples/gallery/internal/gallery/gallery.go) uses `shells/sidebar` and owns demonstration content and state. Examples demonstrate ordinary consumer integration; gallery behavior does not belong in public components.

### Presentation state

Production startup stores application data under `~/.onevra`. The disk-free `Gallery.New` path keeps examples and native tests isolated from real settings.

- `state.json` retains window geometry, sidebar width and expansion, the named navigation route and the last shown application version. Window geometry, including maximized and full-screen state, goes through MyGo's window-state store; Gallery only maps it into this file.
- `config.json` retains appearance, language, and command-palette preferences. Changes apply and save immediately.
- Interactive example values remain in memory, isolated between pages and variants. User content is never persisted.

Unknown routes and unreadable files fall back to defaults; read and save errors are logged. MyGo centers a restored window that would not show on any connected display. An explicit `-theme` launch argument temporarily overrides the saved appearance without rewriting it.

Gallery's application version stays aligned with `mygo.json`.

### Navigation and previews

The grouped sidebar contains Welcome, the Lucide library, a single MyGo entry and Onevra component pages in purpose-based groups. Every page demonstrating MyGo's own components, plugins, APIs or desktop integrations, including System notifications, sits behind the MyGo entry, which reopens the last one shown; an in-page list groups them by the same purposes, and narrow content replaces it with a selector. Pending upstream decisions are startup reminders rather than navigation markers. Both the sidebar and the MyGo list start with a New components group holding pages added since the latest release, followed by an Updated components group listing pages whose components changed since then; pages in either group leave their purpose groups. A release keeps both groups until the first later change returns its published pages to their purpose groups, as the [code-owned lists](../../source/examples/gallery/internal/gallery/navigation.go) describe. Command search lists every page, including each MyGo page. Named routes remain stable when catalog order changes.

Welcome is a promotional page: the product name, repository link, command search and the Gallery version, over a faint tilted field of Lucide icons. The field paints a small cached icon sample directly and passes the pointer through. The repository link opens through MyGo's shell integration; headless views never open URLs. Welcome plays a brief entrance animation that MyGo completes immediately under reduced motion. Development builds, as reported by `mygo.IsDev`, show a Dev badge in the sidebar header and a pixel grid behind every page, which MyGo pages confine to the selected example beside their list; Welcome and Terminal keep dedicated backgrounds. Examples remain interactive and use independent state per variant. The titlebar names each page, so content never repeats that name or adds source listings, hints or tutorial prose; page-level sample actions, such as adding graph notes, sit in the titlebar's trailing toolbar. MyGo pages give the selected example its own titlebar for its name and actions, while the window titlebar names the MyGo entry. Manual procedures belong in the [development guide](../build.md#native-review). Supporting controls use Onevra equivalents whenever available.

Onevra previews omit disabled variants. Closely related components, such as the color pickers, the data charts or the split panes, share one page with a section each; command search also finds the page by each component name. Text and Collapsible variants stack; NativeSelect appears below custom Select examples; other variants wrap where appropriate. The gallery-only Lucide catalog is generated by [lucidegen](../build.md#updating-lucide-icons) and virtualized through GridView; ordinary consumers retain no full-library registry.

### Commands and settings

Command+F on macOS, Ctrl+F elsewhere, and the sidebar search button open the public command component. It searches localized page names and English aliases, navigates to pages and opens Settings. Opening clears the query; activation closes the palette. Shortcuts remain window-local and wait behind modal surfaces.

Settings controls whether results appear immediately or after a search. On macOS, optional ABC selection applies while searching and restores the preceding input source on dismissal, preserving a different source manually chosen while open. Search state stays in memory.

The settings toolbar action opens a Onevra Dialog over the current page. macOS Settings… with Command+, targets the main Gallery window even when another window is focused, restores it if hidden or minimized, and leaves the startup entrance when necessary. The public Settings component owns presentation; Gallery owns values, dialog lifetime and persistence. Narrow surfaces use a category selector, and notification-template edits never send notifications.

### Retained examples

| Page | Integration boundary |
| --- | --- |
| Content display / Markdown | MyGo `ui/markdown` over a cached [fixture](../../source/resources/markdown.md), with resource images, gallery-owned links, an interactive custom code block and a gallery-drawn inline math renderer |
| Content display / Chat | Conversation folding, bounded details, composer pickers, attachments, context meter and usage limits, and a simulated streamed reply started from Send or the titlebar; no model or file access |
| Plugins / Terminal | MyGo shell session, retained across navigation and closed with Gallery; titlebar find and clear, and a menu mirroring the session into a second terminal |
| Charts / Data charts | Bar, line, area, stacked bar, donut, bubble and split bar charts of the public chart component in fixed tiles, each with its own selection and title-row tools that update data, hide the legend, show the empty state and add or remove bubbles |
| Layout & containers / Transforms | Editable Onevra controls and anchored popovers under composed transforms, plus a perspective card |
| Layout & containers / Motion | Retargetable spring presets, replayable keyframes, animated poses and a record turning at a chosen frame rate over cached grooves |
| Desktop / Zoom | Zooms the whole Gallery window through MyGo; the zoom stays across pages until reset and is never saved |
| Games / Canvas | Offscreen canvas, smooth and pixelated bitmap regions and painter transforms |
| Code & diffs / Code editor, Diff viewer | MyGo `ui/editor` used directly; in-memory buffers with gutter changes and highlighted matches, a read-only snippet, editable diffs and hunk actions |

The [chart examples](../../source/examples/gallery/internal/gallery/control_chart.go) use Onevra's public [chart component](components.md#charts) on one page with localized application-owned data. The [motion examples](../../source/examples/gallery/internal/gallery/mygo_motion.go) use MyGo's animation methods directly. Neither creates native resources, background loops or timers; animation lifetime follows the built elements and MyGo's reduced-motion preference.

Terminal starts the user's default login shell on first entry. MyGo owns shell selection, the pseudo-terminal, emulation, search and input. Gallery owns asynchronous native-library loading, the retained session and its find bar; headless views never start a shell. The mirror is a second terminal fed `Terminal.NewMirror` frames at the session's size, as a multiplexer's window is; what is typed there goes to the shell, and it closes with its menu item or the session. Packaging and the bundled-library path adapter belong to Gallery, not the library. See [app bundles](../build.md#app-bundles).

### Native resources

| Page | Creation and cleanup |
| --- | --- |
| Desktop / System notifications | Explicit send action requests delivery; replacement or shutdown withdraws the demo notification |
| Feedback & overlays / Flyout | Actions open parent-owned native windows, one a web page that sizes it; MyGo owns placement, dismissal and parent lifetime |
| Content display / WebView | Gallery retains the native view, refills its background with the current theme, hides it under modal layers and shares a cookie store with the page's own document.cookie; it compiles content rules off the UI thread and applies them to hide the page's demonstration ad; it shows the page's theme color and sound, mutes it on request, opens user-requested windows in the browser and refuses pop-ups the page opens on its own; cookie calls happen only in the native window |
| Desktop / Audio | Sounds are synthesized in memory on first use; the loop plays its intro once and, on request, shows in the system's media controls, which can play and pause it; Gallery close stops it and clears those controls. Headless views never open an audio device |
| Desktop / system services | The System information page presents the desktop's appearance, fonts, languages and formats, network state and credential store as tabs; Recent documents, File watching, Global shortcuts and Native dialogs stay separate pages. All call MyGo only in the native window; store, dialog and system queries run off the UI thread and return through the gallery window; the network listener, folder watch and registered shortcut end when Gallery closes. Headless views never call the running app |
| Games / Game loop | The fixed-step loop runs only while the page shows; native windows read gamepads, headless views never load controller frameworks |

Gallery's own tray and Dock menu are application integrations rather than pages: the standalone entry point installs them, disk-free `Gallery.New` leaves both off, and Gallery close destroys the tray and restores the previous Dock menu unless another owner replaced it. The tray follows the shared [tray convention](../build.md#tray-convention); each show creates its popover. The main window keeps normal close-to-quit behavior. Notification clicks restore Gallery to their page. Dock actions target their owning Gallery independently of the focused window. Flyout editor and system-popover variants retain their note in application memory.

Native resources are never created merely by rendering a page. Platform requirements and manual interaction procedures live in the [development guide](../build.md#native-review), including the [tray and Dock menu](../build.md#gallery-tray-and-dock-menu) and [notifications](../build.md#notification-example).

## Interface language

Gallery offers English, Simplified Chinese, Traditional Chinese, Japanese, Korean and Follow system. The saved preference updates application content, component labels, Shell controls and auxiliary windows immediately. Follow system matches the user's preferred languages, never a saved choice, and follows their changes while Gallery runs; unsupported languages fall back to English. Disk-free examples default to English.

Gallery's messages are MyGo catalogs (`locales/en.json` and one file per translation) whose typed functions `mygo generate` writes into the `locales` package. Stable message keys remain independent of source copy, route IDs, widget keys and stored values. Formatted messages use the typed functions; static text uses keys, and existing demonstration metadata resolves through the English catalog. Choosing a language also calls `mygo.App.SetLocale`, so MyGo's and Onevra's [own strings](components.md#localization) follow; MyGo has no Korean strings, so its own controls and role menu items stay in English there. Language changes preserve drafts, selection, dialog state and navigation.

Keep both catalogs equivalent and preserve ICU placeholders; regenerate the functions after editing them. Translate complete messages, component display names and every menu item Gallery labels itself; MyGo translates role items. API and icon identifiers, filenames and editable fixture content remain unchanged. Installed menus update without losing callbacks or ownership.

## Component review

The [code-owned decision map](../../source/examples/gallery/internal/gallery/mygo_review.go) and its startup reminders distinguish replacements, exclusions, retained upstream examples, newly discovered entries and composition primitives. This describes maintenance decisions and example coverage, not every application call site or transitive dependency.

Generation scans exported free functions taking a context first in MyGo's top-level `ui` package, across platform files and including generic constructors. It omits Base constructors and tests. Generated names and locations are checked in, so running Gallery needs neither a toolchain nor a module cache.

The hand-built catalog and reviewed-subpackage map supplement the scanner for methods, `ui/chart`, `ui/editor` and plugins. Native menus, every MyGo plugin, including the game plugin under Games, audio, canvas drawing, shaders, gradients and blur, transforms, motion and code editing remain direct-use APIs. Standard charts use Onevra's chart component over upstream primitives, while streaming continuous series use `ui/chart` directly; the decision map records that boundary.

After every MyGo upgrade, run `GOWORK=off go generate ./examples/gallery/internal/gallery` from `source/` and review the diff. Ordinary running, building and [packaging](../build.md#app-bundles) use the checked-in snapshot. A generation run cannot establish coverage of new methods or subpackages; review release notes and public signatures too.

Record replacement and exclusion reasons in the decision map, never in generated files. Both hide upstream examples and reminders without affecting Onevra demonstrations. New entries remain visible for review without synthetic examples or build failures. Decisions are neither interactive nor persisted in user settings.

## Verification approach

Ordinary tests use headless views and never open windows. Opt-in native tests run MyGo with temporary user data and capture light, dark and narrow layouts. macOS captures use hidden windows, an accessory process and a test-only AppKit display pump. Foreground lifecycle and input checks need a separate opt-in; other platforms require their own desktop review. See [native review](../build.md#native-review).

`TestNativeCharts` captures selection and data-update transitions on the data charts page; `TestNativeMyGoFeatures` captures transform and motion variants. Both include narrow Chinese content inside Shell. Headless interaction coverage includes chart selection, legend visibility, data updates and empty states, transformed editors and popovers, reduced-motion replay, code and diff editing, canvas redraws, held-key game steps and physical-key command shortcuts.

Captures omit OS-composited blur and do not prove pointer, input-method or assistive-technology behavior. Review those interactions, both languages and themes, text scaling, window controls and sidebar resizing in a desktop session. WebView needs its own page capture because window captures leave its native content transparent. Terminal review exercises its real shell and cleanup.
